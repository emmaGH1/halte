# Halte · Independent judging and engineering review

23 November 2026 · Target: Post-Quantum dApp · Internal freeze: 30 November

**Verdict.** Halte has a real QoreChain integration and a memorable product moment. The contract really does move a passport from active to frozen and back using ML-DSA-87. Today I would pass the four track requirements on the available evidence, subject to organizer review, and hold the prize. The submission sends judges to a README for the old prototype. The demo dealer could never complete the advertised transfer. Anyone with a passport link can ask the demo server to act as its owner. Most importantly, an ordinary successful transfer leaves the previous owner's other offers executable.

I fetched the production landing page, passport and public project page, inspected the stored desktop and phone screenshots, extracted both QCAI PDFs, and independently checked Diana receipts, events, bytecode and registry state. I rebuilt in a temporary directory using the installed dependencies and ran all 11 Hardhat tests successfully. I used read-only requests against Diana and did not run the write-heavy status journey. The video was assessed from file metadata and the supplied run order. Website interaction findings below distinguish source inspection from live HTTP observations. Severities describe submission risk or impact on the trust promises. Hours are hands-on estimates, with overlapping fixes grouped in the final list.

## 2. Product and story

This is useful for a low-friction testnet demo and fatal as evidence of exclusive human owner control. A shared link effectively exposes controls for records owned by that service account. Bind writes to a server-validated demo session and the passport it minted, with shareable read-only views. State before mint and next to the controls: “Halte signs for a testnet demo account. This browser session controls this demo passport.” Separately, if feasible, use a funded testnet owner held outside Vercel to sign the digest locally, have a distinct account relay it, and publish the successful sender/holder distinction. Keep the public one-click flow. A wallet prompt alone would leave the custody claim unresolved.

## 3. Contract and signing design

- **Critical · A prior owner's offers survive a completed handoff · 4–6 h including regressions, plus release and audit.** `contracts/contracts/Halte.sol:68–91` stores each offer's epoch. A successful accept deletes one offer, updates owner and increments nonce, but leaves epoch unchanged. Another offer opened by the previous owner remains current and can transfer the passport away from the new owner without that owner's consent. This is a source-confirmed invariant violation. Increment epoch on every successful transfer, keep nonce invalidation, update the epoch semantics and prove two old offers die on any handoff while a newly issued offer is usable. Add a test for the old owner's signed authorization across that handoff. `web/app/p/[id]/page.tsx:95–99` would incorrectly label an ordinary transfer “Recovered” after this fix. Render recovery using an actual `Recovered` event.
- **Major · Registered key is treated as proven possession · 2–4 h, shared contract release.** `Halte.sol:5–7,152–158` decodes three returns and accepts any nonempty algorithm-1 public key. QoreChain's documented fourth output is `possessionProven`. Live Diana returns it, true for the demo owner. General mint/recipient admission and action verification ignore it. This weakens the guarantee that a holder can freeze and recover, allowing records linked to keys without verified possession. Require the fourth flag and exact 2,592-byte key size. Test no proof, wrong algorithm, missing registry and malformed responses. Keep the ABI and mock aligned. [Official precompile interface and PoP guidance](https://docs.qorechain.io/developer-guide/evm-precompiles/).
- **Major · Transfer authorization is classical during a live window · 2 h to specify/test the model, 6–10 h for a PQ transfer-intent change.** `Halte.sol:68–101` gates offer creation and cancellation on `msg.sender` and accept on the selected dealer and their key registration. A live in-scope EVM window admits ordinary EVM writes, so its hybrid opening does not imply PQ consent per offer. `docs/PLAN.md:10` overstates the classical-key guarantee. The limit is especially material with the runtime window's 200-transaction budget. Narrow the window, document the in-window threat, and demonstrate which specific operations require PQ approval. If widening the security claim, require an owner PQ signature binding dealer, passport, ownership generation and expiry when issuing a transfer authorization. Recovery of a *frozen* passport already requires PQ consent. [QoreChain window workflow](https://docs.qorechain.io/build-before-qday/workshop-1/).
- **Major · “Report” wins only once included · 1–2 h to state and test the ordering.** `Halte.sol:78–91,109–117,134–144`. If an eligible dealer's accept lands first, holder and nonce change and the old owner's report cannot freeze the new owner's passport. That is the natural ordering in this ownership model, but the UI implies protection at click time. Use “Submitting” until the receipt. State that confirmed chain order decides and prompt a reread if ownership changed. Add both orderings to regressions. Defer a transfer challenge period or authenticated dispute process.
- **Major · Lost credentials and third-party reports have no product path · 2 h to document/test registry behavior, 12–24 h for a designed recovery feature.** `Halte.sol:109–126,142–158` resolves the current registered key at execution. A QoreChain key rotation can supersede the original key for an existing passport, subject to native authorization rules. If no usable PQ key can be restored or rotated through that registry, a frozen passport can be stuck. Explain backup, rotation and relay assumptions. Test that a legitimate replacement key supersedes an old signature and what a missing key does. Preserve permissionless relay of an owner authorization. A police report, insurer or dealer can be an off-chain alert with its own provenance, but granting on-chain freeze/recovery power requires a separate trust model with explicit scope and abuse controls. Keep that out of the freeze sprint.
- **Minor · Offer lifetime and event semantics need cleanup · 2–4 h contract plus tests, after the main invariant.** `Halte.sol:28–44,68–102` has no expiry or zero-address validation. Stale entries are still stored, although no on-chain scan makes this a bounded-gas operation. Add short expiry and reject invalid recipients if touching offer semantics. Existing creation, transfer, cancel, freeze and recover events are sufficient to reconstruct the timeline. Consumers must infer offer invalidation from generation changes. Avoid per-offer invalidation events or a loop over outstanding offers. Document optional cleanup and use a bounded, indexed read off chain.
- **Minor · Mock tests leave PQ boundaries implicit · 2–4 h, partly covered by the fixes above.** `contracts/test/Halte.ts:14–43,104–153` derives the digest under test from the same contract and verifies synthetic signatures. Add focused independent digest vectors for passport/action/contract separation, exact expiry boundary, nonce invalidation and registry rotation. Verify failure when either precompile is unavailable. Treat maintained live evidence as the integration test for real ML-DSA rather than calling the mock suite cryptographic validation. Keep the fail-closed behavior of `_checkPq` and the existing domain, nonce and expiry separation.

## 4. Web app

- **Major · A fresh shared link drops the history and proof · 5–8 h.** `web/app/p/[id]/page.tsx:24–46,166–188` stores timeline and signature in `sessionStorage`. The offer only follows the optional query parameter. A clean tab gets current state from the API and an empty register, and can show “Owner signature · awaiting a signed report” for a recovered passport. Fetch the indexed lifecycle events for that one ID. Give each confirmed event a block and receipt. Treat simulations as separate timestamped checks with their own evidence. Replace clipped full-signature microprint and fake zeroes with a compact digest or fingerprint and an expandable proof view. Copy the full ID, contract and holder address. This lets a juror share an actual record.
- **Major · Wrong, missing and stale data can look authoritative · 4–6 h.** `web/app/api/passport/[id]/route.ts:9–20` doesn't check that the queried offer belongs to the passport before computing its live state. An unrelated offer from the same epoch can be presented as this passport's. Nonnumeric `?offer=oops` returned an empty 500. A nonexistent all-zero bytes32 returned HTTP 200 and status none. `page.tsx:30–34,95–115,143–150` silently ignores typed API errors, has no network error handling on refresh, renders the ordinary holder headline for status none, and claims “registered” when the registry read yields zero. Validate bounded decimal offer IDs and passport linkage, give absent records a real 404, and distinguish loading, unavailable, missing, expired, cancelled and stale. Render a retry on read failure and disable actions on unverified state. Read coherent state at one block and refresh after confirmed writes and tab focus, with an as-of indicator.
- **Major · Mobile hierarchy asks users to hunt for the action · 3–5 h, overlaps the proof view.** Stored phone images put a nearly full-width illustration before the first CTA, and the certificate and signature art before the controls. Current code retains this order (`web/app/globals.css:107–115`, `web/app/p/[id]/page.tsx:119–195`). Put “Issue a demo passport” in the first phone viewport, point the header CTA at the actual control, and group owner and dealer actions next to the current status and offer outcome. Move the certificate details behind the story. The lever is distinctive. Use the red stamp for a confirmed state change on the interactive passport and label the landing animation as illustrative. Test 320–430 px, large text and zoom. The older screenshots include a Next dev indicator and superseded navigation, so use fresh captures for the submission.
- **Major · Screen-reader and keyboard flow are incomplete · 2–4 h.** `web/app/mint.tsx:17–21`, `web/app/p/[id]/page.tsx:174–197` lack an announced status or error for results. `web/app/ui.tsx:76–115` supports Escape and `aria-expanded`, but has no focus management or inert background on the full-screen menu. `web/app/globals.css:19,90–93,237–258` uses faint 9–11 px secondary labels and only partial reduced-motion treatment. Give meaningful text and focus to status, results and retries, restore focus after menu dismissal, provide visible keyboard focus, and cover logo and sheet motion as well as the calibre. Test contrast and navigation on a real phone or device emulator with keyboard and screen reader. Decorative certificate microprint should stay out of the accessibility tree.
- **Minor · The landing proof makes RPC failure look like success · 2–3 h.** `web/lib/live.ts:18–26,35–55` scans both event families from deployment in 9,000-block chunks on each revalidation and renders `ok` after a height read even if all proof requests fail. `web/app/page.tsx:56–69` calls cumulative `Frozen` event count “frozen,” labels a failed key read “registered,” and displays “verified by pqcVerify” even below “none yet.” Cache a bounded snapshot or use a pinned proof receipt, degrade each field explicitly and use “freeze reports” for event counts. Move secondary art out of the initial proof rendering path and measure slow-phone performance before tuning font or SVG budgets.

## 5. Ops, reproducibility and evidence

- **Critical · Public signing is an availability bottleneck · 5–8 h shared with custody containment.** `web/app/api/[action]/route.ts:11–36` has no effective session authorization, rate limits, shared budget or idempotency. `web/lib/chain.ts:81–118` uses a single signer and checks only remaining transactions and blocks before reusing a window. It doesn't validate the actual target set, remaining value or native-only mode. Concurrent functions can race the native window sequence and EVM nonce. A confirmation timeout or failed post-receipt read can leave the user thinking a write failed after it landed. Isolate a capped testnet account, bind writes to sessions, limit mint/sign cost, and coordinate the signer across serverless instances with a durable queue or lock. Read back scope/remaining allowance and return the transaction ID on submission so the client can reconcile. Keep a clean read-only reference passport available during network failure or exhausted write budget. At review time Diana reported 91.306316 QOR for the signer and 182 transactions left in the active window. Those are a snapshot, not a judging-period availability guarantee.
- **Major · “Refused” can be a transport failure · 3–5 h.** `web/lib/chain.ts:121–132` maps any simulation exception to a refusal. The UI sets `data-demo=refused` for any reason and the checks largely assert the marker and unchanged status (`checks/journey.mjs:119–155`). Check for the exact decoded custom error and separate RPC failure from contract refusal. Record block, contract, call kind, dealer or simulated signer, the referenced offer/passport and returned selector. Verify owner before and after. With a real PQ dealer, add the successful simulation control before freeze. Keep the refusal text precise: “Diana simulation rejected this transfer.” A simulation has no receipt or broadcast hash.
- **Major · A green board leaves most scored claims unchecked · 3–5 h.** `checks/journey.mjs:45–57,84–117` checks generic transaction success separately from current state and treats an app marker as proof of PQ verification. J3 lacks an independent call or owner comparison, J3! saves no evidence, and J4 accepts a generic refusal. `scripts/status.mjs:164–172` can fall back to the local git SHA if live identity is absent, and :212–214 overwrites latest evidence after issuing live actions. `scripts/check-live.mjs:6–20` is a placeholder and exits 1 as shipped. Implement a credential-free judge verifier against pinned receipts, events, target selectors, expected owner, offer and epochs, chain ID, scoped native-window message and hybrid event. Compare app version and runtime hash explicitly. Keep this read-only path separate from the mutable progress runner. Get approval for changes to the approved journey checks, as `docs/PLAN.md:3` requires.
- **Major · Source-to-deployment and clean setup instructions need packaging · 2–4 h.** `evidence/deploy/0x1e2bacc937a116a281e13e2932f227e0048e91c5.json` records `sourceCommit: null`. `/version.json` returned web deploy `70ed2be` while local HEAD was `2ed22af`. This is consistent with newer docs, but neither value identifies the audited contract in the release manifest. `contracts/README.md:1–6,25–26,83–102` still documents Counter and Ignition and gives `PRIVATE_KEY` or keystore as setup while actual `scripts/deploy.ts:13` requires the mnemonic. Document Node 22, pinned lockfile commands for each package, test commands without credentials, the archive's exact compiler profile and bytecode comparison, and an optional disposable Diana setup. Clarify that deploy opens a one-transaction creation window then a target-scoped runtime window. Replace the fixed sleep with explicit receipt/window polling if editing that path. Document funding, safe secret-variable names without values, and the owner/dealer account role split. Credit fonts and check their redistribution terms before shipping.
- **Minor · The repo's status snapshots compete · 1 h.** `docs/STATE.md:7,27,30,50` still says audit and tests next, lists ten tests, and says custody labeling is future. The stand-alone latest board says five steps passed. Keep one dated release checklist and index the reproducible evidence for that release. Preserve historical runs with their IDs. A high count of dated JSON snapshots adds little if a judge cannot identify the one matching the film.

## Things I would explicitly not do

- Build payments or a marketplace, token/NFT wrappers, real brand onboarding, physical authenticity or a new registry integration before the freeze.
- Add an admin override, guardian quorum, insurer authority or public theft-report freeze. Those change who can control a passport and need deliberate design.
- Build an entire browser wallet under deadline pressure. The low-risk stretch is one documented owner-held signature with an independent relayer.
- Spend time gaming the QCAI score, adding a caller balance threshold or blocking legitimate relayers with an owner-only caller requirement.
- Broadcast deliberately reverting testnet writes just to acquire a transaction link. A well-specified historical Diana call and a positive control make stronger evidence per hour.
- Replace the watch art, refactor the frontend framework, add a full indexer, or rerender the long film before the proof frame and public entry work.
- Spend the freeze buffer chasing special-award polish, gallery positioning or an unconfirmed claim about first-of-its-kind provenance.
